# Equivariant_pathway

p4m-equivariant maze policy + full active-loop cycle (Baseline DAgger / P4 / P5 / P6).

## What this pathway is

A drop-in alternative to `CNN_pathway/`. Same input maze, same fixed-test
layouts, same LLM analysis pipeline (P4 / P5 / P6). The model is the
**EquivariantUNetPolicy** from the dmnpol repo — three stacked p4m-
equivariant 3×3 convs (no pooling, dilation 2 in the last block) fed by
a 5-channel semantic encoding of the grid (agent, goal, fire, wall,
free). escnn provides the group convolutions; the policy is built-in
equivariant under the 8 elements of p4m.

Why use it: on a 5×5 maze the equivariance is already built into the
architecture, so we don't pay the augmentation cost the CNN pathway
absorbs and, more importantly, the policy generalises to symmetric
layout variants (left-corridor failure -> right-corridor failure)
**without** an extra demo on the mirrored case.

## Layout

```
Equivariant_pathway/
  model.py                 # EquivariantUNetPolicy (escnn-based)
  encoder.py               # (5, H, W) semantic-channel encoder
  expert.py                # BFS A* + multi-label optimal-action mask
  dataset.py               # JSON demos -> (input, optimal_mask) samples
  train.py                 # multi-label BCE training loop, checkpoints
  rollout_test.py          # rollout on a layouts YAML; full_output.json
  collect_demos.py         # BFS demo collector (yaml + recommended.json)
  layout_sampler.py        # 50 random heldout layouts -> yaml
  layout_tracker.py        # persist layouts as JSON + per-layout PNGs
  baseline_dagger.py       # DAgger baseline (no LLM, retrain every 4 demos)
  analyze_p4.py            # P4 LLM analysis wrapper
  analyze_p5.py            # P5 LLM analysis wrapper (KAG + RAG)
  analyze_p6.py            # P6 LLM analysis wrapper (KAG + RAG + TKF)
  _analysis_common.py      # shared profile-runner logic
  charts.py                # 4 line charts: baseline vs P4/P5/P6
  run_full_cycle.py        # end-to-end orchestrator (THIS is the entry point)
  training_layouts.yaml    # 5 hand-designed layouts (2 reps each = 10 demos)
  test_layouts.yaml        # 4 hand-designed held-out test layouts
  heldout_test_layouts.yaml  # auto-generated by layout_sampler.py (50 layouts)
  demos/                   # initial 10 BFS-expert demos go here
  checkpoints/             # initial best_eq_policy.pth goes here
```

Each method (Baseline DAgger / P4 / P5 / P6) operates on a fully
isolated subtree under `results/equivariant_pathway/cycle_<ts>/`:

```
cycle_<ts>/
  setup.json
  training/    layouts.json + images/<name>.png        (5 train layouts)
  test/        layouts.json + images/<name>.png        (4 test layouts)
  heldout/     layouts.json + images/<name>.png        (50 random)
  baseline_dagger/
    demos/        # initial 10 + correction demos
    checkpoints/  # last_eq_policy.pth + best_eq_policy.pth
    rounds/round_<N>/
      dagger_pass/dagger_pass_summary.json
      heldout_eval/full_output.json
      heldout_failures/layouts.json + images/...
    learning_curve.json
  p4/  # same shape, but with rounds/round_N/{test_rollout,p4_analysis,prescribed_layouts,test_failures,heldout_eval,heldout_failures}
  p5/  # same shape (with per-round rag_bank/round_N/)
  p6/  # same shape (with per-round rag_bank/round_N/)
  charts/
    baseline_vs_p4.png
    baseline_vs_p5.png
    baseline_vs_p6.png
    baseline_vs_all.png
    summary.json
```

## End-to-end run

```bash
python -m Equivariant_pathway.run_full_cycle \
    --methods baseline_dagger,p4,p5,p6 \
    --initial_demos 10 \
    --initial_epochs 200 \
    --round_epochs 60 \
    --heldout_n 50
```

The orchestrator:

1. Generates `heldout_test_layouts.yaml` (50 random 5×5 layouts) if it
   doesn't already exist; persists train/test/heldout layouts as JSON +
   PNGs under `cycle_<ts>/{training,test,heldout}/`.
2. Collects 10 BFS-expert demos from `training_layouts.yaml`, writes
   them to `Equivariant_pathway/demos/`.
3. Trains the equivariant policy on those 10 demos, saves
   `Equivariant_pathway/checkpoints/best_eq_policy.pth`. **Every** method
   copies this checkpoint as its starting point — no method gets a
   head-start.
4. For each method, loops:
   - rollout on `test_layouts.yaml` (writes `full_output.json` for the
     LLM to consume)
   - **profile methods (p4/p5/p6):** run `analyze_p<N>.py` -> get
     `recommended_layouts.json` -> BFS-collect those into
     `<method>/demos/round_<N>/` -> retrain on UNION of all demos in
     `<method>/demos/`
   - **baseline_dagger:** rollout-and-correct in-line (BFS recovers each
     failure from the step BEFORE the fire-hit; corrective demo
     appended to `<method>/demos/`); retrain after every 4 corrective
     demos
   - eval on `heldout_test_layouts.yaml` (50 layouts), record
     round metrics (`heldout_success_rate`, `additional_demos_collected`)
   - **stop** when `heldout_success_rate >= 0.90`. **No 5-round cap.**
     A 50-round guard is in place purely to prevent runaway loops; it
     can be raised with `--max_rounds`.
5. Produces 4 line charts (baseline vs each profile + combined).

## Running methods in parallel

For real CPU/GPU parallelism, launch each method in its own process:

```bash
for m in baseline_dagger p4 p5 p6; do
  python -m Equivariant_pathway.run_full_cycle \
      --methods $m \
      --cycle_dir results/equivariant_pathway/cycle_shared \
      --skip_initial_collect --skip_initial_train \
      --skip_charts &
done
wait
python -m Equivariant_pathway.charts \
    --cycle_dir results/equivariant_pathway/cycle_shared
```

The directory layout guarantees that each method only ever reads/writes
its own subtree, so there's no contention on demos / checkpoints / RAG
bank between concurrent runs.

## Dependencies

In addition to DmNfull's existing requirements, this pathway requires
**escnn** for the equivariant convolutions:

```bash
pip install escnn
```
